# AIエージェント開発の小さなサンプル

ここでは「届いた問い合わせを分類し、返信案を作るエージェント」を考えます。

最初から自動送信はしません。分類と返信案の作成までをAIが担当し、最後は人が確認します。

## まず、普通のAIとの違い

質問に1回答えるだけなら、AIチャットで十分です。

AIエージェントは、目的を受け取り、必要な情報を確認し、決められた道具を使い、結果を検証します。

```text
目的を受け取る
    ↓
状況を確認する
    ↓
次の行動を決める
    ↓
道具を使う
    ↓
結果を確認する
    ↓
完了、または人に相談する
```

この繰り返しを、ここでは「エージェントのループ」と呼びます。

## 今回の目的

問い合わせを次の3種類に分類し、返信案を作ります。

- `question`：使い方などの質問
- `bug`：不具合の報告
- `other`：どちらにも当てはまらないもの

## 入力と出力を先に決める

入力例：

```text
保存ボタンを押しても画面が変わりません。
ブラウザはSafariです。
```

出力例：

```json
{
  "category": "bug",
  "summary": "Safariで保存ボタンを押しても反応しない",
  "reply_draft": "ご報告ありがとうございます。発生した時刻とSafariのバージョンを教えてください。",
  "needs_human_review": true
}
```

出力の形を先に決めると、後続処理とテストが簡単になります。

## エージェントの処理

特定のプログラミング言語に依存しない疑似コードで表すと、次のようになります。

```text
function handleInquiry(inquiry):
    if inquiry is empty:
        return error("問い合わせが空です")

    category = classify(inquiry)
    summary = summarize(inquiry)
    replyDraft = createReply(inquiry, category)

    result = {
        category: category,
        summary: summary,
        reply_draft: replyDraft,
        needs_human_review: true
    }

    if result does not match the required format:
        return error("出力形式が正しくありません")

    return result
```

ポイントは、AIにすべてを自由に任せていないことです。

- 入力が空なら処理しない
- 分類先を3種類に限定する
- 出力形式を固定する
- AI自身には送信させない
- 最後に形式を検証する

## 道具を追加するとき

最初の版では、外部の道具はなくても構いません。必要になったら、一つずつ追加します。

| 道具 | できること | 主な注意 |
| --- | --- | --- |
| FAQ検索 | 過去の回答を探す | 古い回答を使わない |
| 顧客情報の参照 | 契約内容を確認する | 閲覧範囲を制限する |
| チケット作成 | 担当者へ引き継ぐ | 重複作成を防ぐ |
| メール送信 | 返信を送る | 人の承認を必須にする |

道具には、必要最小限の権限だけを与えます。「検索」と「更新」は別の道具にすると安全です。

## 最初のテスト

最低でも、次の4種類を試します。

1. 分かりやすい質問
2. 分かりやすい不具合報告
3. 判断しにくい問い合わせ
4. 空の入力や非常に長い入力

期待する分類と、実際の分類を記録します。うまくいかなかった入力は消さず、次回も試すテストケースとして残します。

## 次の一歩

このサンプルを実装するときも、最初は自動送信を付けず「結果を画面またはファイルに表示する」ところまでにします。安全に動くことを確認してから、FAQ検索やチケット作成を一つずつ追加しましょう。

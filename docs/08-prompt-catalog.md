# AIへの依頼文（プロンプト）のカタログ

`[]` の部分を自分のプロジェクトに合わせて書き換えてください。

## 1. コードベースを理解する

```text
[機能名]の処理の流れを調べてください。
入口、主要な関数、データの保存先、関連テストを示してください。
まだ変更はしないでください。
```

## 2. 小さな不具合を修正する

```text
[再現手順]で起きる[症状]を修正してください。
変更範囲は[ファイルまたは機能]です。
原因を説明し、再発防止テストを追加してください。
```

## 3. テストを追加する

```text
[対象]の既存動作を変えずにテストを追加してください。
正常系、境界値、代表的な失敗を含めてください。
実装上の都合ではなく利用者から見た動作を検証してください。
```

## 4. リファクタリングする

```text
[対象]を読みやすくしてください。
外部から見える動作は変更しないでください。
変更前後で同じテストが成功することを確認してください。
```

## 5. コードレビューする

```text
この差分をレビューしてください。
重大な不具合、セキュリティ、互換性、データ損失、テスト不足を優先してください。
要約より先に、具体的な問題と該当箇所を示してください。
```

## 6. 計画だけ作る

```text
[目的]を実現する計画を作ってください。まだ実装しないでください。
変更候補、手順、テスト、リスク、ロールバックを含めてください。
確認が必要な仮定を分けてください。
```

## 7. ドキュメントを更新する

```text
[コード変更]に合わせて利用者向け文書を更新してください。
コードから確認できない仕様は追加しないでください。
古くなった説明も探してください。
```

## 8. 依存関係を調べる

```text
[ライブラリ]を追加する必要があるか調べてください。
標準機能と既存依存で代替できるか、保守性、サイズ、ライセンスを比較してください。
まだ追加しないでください。
```

## 9. エラーを調査する

```text
次のエラーの原因を調べてください：[エラー]
再現条件、根本原因、最小の修正案、確認方法を示してください。
証拠がない推測は仮説として分けてください。
```

## 10. 完了前に確認する

```text
変更を完了報告する前に、差分を読み直してください。
依頼外の変更、デバッグコード、秘密情報、テスト不足がないか確認し、
実行したコマンドと結果を報告してください。
```

## 組み合わせ方

最初に「理解する」または「計画だけ作る」を使い、人が確認してから「修正する」へ進むと安全です。最後に「完了前に確認する」を組み合わせます。

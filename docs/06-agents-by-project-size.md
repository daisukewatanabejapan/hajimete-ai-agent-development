# プロジェクト規模ごとのAGENTS.mdテンプレート

`AGENTS.md` は長いほど良いわけではありません。規模に合わせて、必要な判断だけを残します。

## 個人プロジェクト

対象：1人、単一アプリ、短い開発サイクル。

- [テンプレートを開く](../examples/scales/AGENTS-solo.md)
- プロジェクトの目的、テストコマンド、変更禁止事項を中心にする
- 承認者は自分なので、危険な操作の事前確認を明記する

## 小規模チーム

対象：2〜10人、レビューとCIがあるチーム。

- [テンプレートを開く](../examples/scales/AGENTS-team.md)
- 担当領域、PR、レビュー、CI、依存関係追加のルールを含める
- 人しか決められない設計判断を明確にする

## 大規模・モノレポ

対象：複数チーム、複数サービス、異なるビルド方法。

- [テンプレートを開く](../examples/scales/AGENTS-monorepo.md)
- ルートには全体ルールだけを書く
- 各サブディレクトリに、その領域専用の `AGENTS.md` を置く
- 全テストではなく、変更範囲に対応する検証コマンドを示す

## 選び方

| 質問 | はいの場合 |
| --- | --- |
| 開発者は自分だけ？ | 個人用 |
| PRレビューとCIがある？ | チーム用 |
| 複数のビルド方式や所有チームがある？ | モノレポ用 |

最初は小さいテンプレートを選び、同じ説明を繰り返すようになったときだけ項目を追加します。
